发布 v0.3.2 时两次 `git push --atomic` 均在约 21 秒后以 128 退出，无法连接 `github.com:443`。GitHub API 查询正常，远端分支仍在旧提交，未产生部分发布。系统 DNS 返回的 `20.205.243.166` 网络路径不可达；向另一 DNS 服务器查询得到 `172.182.252.133`，通过仅对本次命令生效的 `http.curloptResolve` 指定已查询地址后，分支和标签原子推送成功。规避方式是先查远端状态与 DNS、确认替代解析有效，再临时指定连接地址；不禁用 TLS、不改系统 DNS、不将易变 IP 固化为长期规则。未找到项目事故记录工具，此记录仅本地保留。

## 主分支自动发布配置故障（2026-10-02）

- 三次 Git 传输失败（fetch、普通 push、指定地址与 HTTP/1.1 的 push），均为连接被重置。替代地址不再可靠，而 GitHub API 可用。通过 Git Data API 上传三个公开文件，逐个校验 blob 和整棵 tree 哈希，确认远端 main 未变化后以 `force=false` 更新引用；不上传私人报告、不禁用 TLS、不强推。
- 两次本地重建 API 提交哈希校验失败，均在修改远端引用前停止。根因是 PowerShell 已把 JSON 日期转换为 DateTime，再经字符串 Parse 丢失时区；另有 GitHub API 提交消息不带尾换行与本地 Git 默认带尾换行的序列化差异。改为直接 DateTimeOffset 类型转换并校验精确时区/尾换行后得到 API 返回的同一 SHA。只有哈希完全相符后才更新远端及本地引用，最终提交为 `cb3129a8ae4080cf65e1f716c116d6fd9e00a455`。
- 规避：先使用结构化类型保留时区，内容树与提交对象分别校验，验证失败不得继续修改分支；网络故障应先确认远端状态，避免重复提交或发布。未发现项目事故记录工具，保留本地任务记录，不修改 AGENTS.md。
