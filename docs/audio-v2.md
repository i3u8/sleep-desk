# Audio v2：先检测，再分类

此实现随 0.4.0 测试版提供。它改变录音与分析架构，不代表已达到可靠的鼾声识别准确率，更不提供呼吸暂停、低氧或危险程度判断。旧版 `RuleClassifier` 仅保留历史回归测试，生产录音流程不再调用它。

## 流程

```text
AudioRecord / 固定采集增益
  -> CandidateDetector：定位声音本体
  -> EventDetectionPipeline：生成 UNKNOWN/PENDING 事件和独立检测支持度
  -> ContextualAudioBuffer：等待真实后置音频
  -> BackgroundAudioQueue：有界后台分析
       -> 保存代表录音
       -> YamNetSoundModel：端侧模型窗口推理
       -> SoundClassifier + TemporalSoundFusion：候选与跨事件证据
  -> EventUpdatePublisher：按同一事件 ID / revision 更新
  -> SessionStore / 界面 / 导出
```

事件存在与否由检测层决定。模型不确定、初始化失败、分析繁忙和录音保存失败都不能被解释为“没有发现声音”。同一事件从检测到最终分析始终使用同一 ID；后台结果携带所属会话 ID，不能写进后来开始的另一晚。

## 录音与资源边界

- 16 kHz 单声道；保留原有固定软件增益处理，不做每片 RMS/峰值归一化。索引记录实际增益和录音源。
- 默认 2 秒前文、最长 8 秒声音本体、2 秒真实后文，录音上限 12 秒。模型分类与播放录音的边界分别记录。
- 相邻事件可以共享时间上下文，但不为省文件误合并事件身份。
- 停止或换录音源时只保存已经采到的 PCM。`PRE_ROLL_SHORT`、`POST_ROLL_SHORT`、`CLIP_LIMIT` 等标记可在详情与导出查看；不补静音假装录到了后文。
- 初始背景校准默认 12 秒；切换录音源会重新校准。新检测器不要求候选内存在三次呼吸响度峰。
- 采集线程不运行模型、不做 AAC 编码、不写会话 JSON。分析队列默认 8 项；元数据队列默认 256 个事件，合并同 ID 的较新状态。
- 元数据队列保留一个停止时的额外检测槽，保存触发背压的最后一个新事件；背压会显式停止采集，不无限积压内存。
- 默认每小时最多保存 120 个片段，每会话最多 360 个。达到配额后仍保留事件与分类结果，明确标记录音未保存。
- 关闭 `saveSpeechClips` 时，已知语音、疑似语音、无法排除语音及模型失败均不保存音频；事件仍保留。语音检查覆盖播放片段的前后文，而非仅声音本体。它仍依赖模型证据，不是百分之百排除人声的保证。

## 模型与融合

模型、来源、许可及 SHA-256 固定在 `app/src/main/assets/models/`。启动校验模型，全部推理在设备 CPU 执行，无下载/上传服务。原始标注录音不进入 APK。

- 模型输入按 PCM16 除以 32768 转换，窗口 15600 样本、步长 7680。模型末窗补零与实际录到的后文是两回事，窗口末端只标记真实有效样本。
- 检查模型窗口与声音本体的重叠，防止前文另一个声音主导本事件。
- 综合声音类别的竞争与兼容关系：Snoring 可以与 Breathing、房间背景并存，不能把多标签模型强行当互斥 softmax。
- 短声音无法独立提供完整模型窗口时，候选提示与强定类依据分开；缺失/补零不能被当作可靠的反面证据。
- `SUGGESTED` 只是模型建议，支持度未经本场景概率校准。工程门槛用于拒识，不是医学标准，也不是用 12 个私有样本拟合的分类头。
- 融合仅使用最近 30 秒、最多 64 条历史，关联相邻且不重叠的事件。当前事件必须有自己的模型证据，不能因邻居是鼾声便把无证据声音也改成鼾声。
- 持久化最多 32 个相关/高分模型摘要，不将每帧 521 类全部写入整夜 JSON。

## 数据与界面

新字段向后兼容，旧事件默认 `LEGACY`，不自动重写旧分类：

| 字段 | 含义 |
| --- | --- |
| `detectionConfidence` | 检测支持度，与类别分数分开 |
| `classificationStatus` | PENDING / SUGGESTED / UNCERTAIN / FAILED / LEGACY |
| `confidence` | 未校准的分类支持度，保留旧字段兼容 |
| `suggestedTypes`, `classScores`, `modelVersion` | 候选、模型证据与版本 |
| `clipStatus` | 等待、已保存、达到配额、设置禁止或保存失败 |
| `revision` | 检测0、录音/上下文1、最终分析2；旧更新不能覆盖新结果 |
| `userLabel`, `reviewFlags` | 人工纠正与重点复核，优先于后续自动结果 |

未知、分类失败等事件在关键段与列表可见，可以回听已经保存的录音。人工纠正改变有效展示/计数，但原模型类型保留供溯源。候选只展示少量中文类别，不能把模型分数当成准确率。

重点复核是人工标记，不是自动危险报警。用户纠正或标记的片段在导出时不受普通代表片段配额遗漏。会话存储采用 AtomicFile；停止时将未完成分析明确恢复为失败/待复核状态，而不是永久停留“分析中”。

## 验证入口

- `./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest`
- `tools/verify-android-isolated.ps1 -SourceStable`：仅允许专用模拟器，无其他设备时运行完整仪器测试；不要在有个人记录的真实手机运行会重置测试数据的 E2E。
- `FullAudioPipelineTest`：连续 PCM -> 检测 -> 后文 -> 真实 YAMNet/AAC -> JSON -> ZIP。
- `DetectionReviewE2eTest`：待确认、实时状态、回听、人工纠正、重点复核、导出与历史兼容。
- `TrackingLifecycleTest`：真实前台录音服务的开始、停止、立即重启。
- `PrivateSoundReplayTest`：默认跳过；只在明确提供本机私有夹具时运行，不打包原音。旧导出缺少精确边界，仅能作探索性回放。

实际测试数量、安装包哈希、截图和私有回放结果保存在本轮本机验收记录中。模拟器通过不能替代真机麦克风、整夜功耗和新录音上的分类验证。
